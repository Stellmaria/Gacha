# Архитектура первого прототипа и будущего Telegram-адаптера

## На данный момент

В этой ветке только **автономная браузерная анимация**, без сервера и Telegram. Все розыгрыши демонстрационные: client-side RNG, а не реальный выигрыш. Не применять результаты браузера для начислений.

Рабочее название — Gacha. Единственная игровая валюта — **вельветы** (никаких ₽, VL, AVL). Экономика гачи независима от Dominus/Demian.

## Два режима вместо смешивания таблиц

- Призовой — восемь секторов: [20,20,15,15,10,10,5,5].
- Карточный — шесть редкостей: [25,22,19,16,11,7].
- Эти таблицы нельзя без согласования перемножать, заменять друг другом или автоматически конвертировать.
- Визуальная площадь сектора пропорциональна весу. Указатель находится на 12 часах, CSS вращает колесо к центру целевого сектора.

## Production contract (предложение, НЕ реализовано)

1. Telegram отправляет авторизованное действие `spin`, связанное с `user_id`, `chat_id`, `message_id`, `drop_id` и `mode`.
2. Бот проверяет Telegram identity, права игрока, срок дропа и баланс круток. Нельзя доверять user_id или outcome, присланным виджетом.
3. На сервере создаётся `spin_id`, под PostgreSQL-транзакцией и уникальным индексом по `session_id` фиксируется единственная награда. Конкурирующие запросы получают тот же результат.
4. Сервер выбирает весовой сектор с криптографическим RNG, сохраняет исход, версию таблицы вероятностей, стоимость и экземпляр карточки либо начисление.
5. Ответ (после commit) содержит `spin_id`, `mode`, `sector_id`, `animation_angle`, `version`. Клиент ТОЛЬКО отображает его.
6. Отправка готового изображения карточки — через transactional outbox с `spin_id` как идемпотентным ключом выдачи.
7. При сомнительной Telegram-доставке запрещён бездумный retry; инвентарь и бухгалтерская запись не дублируются.
8. Закрытие/повторное открытие виджета восстанавливает уже подтверждённый результат по `session_id`.
9. Нет переходов между внутренней валютой и реальными деньгами без отдельного решения и проверки Telegram-платежей.

## Widget API и ограничения

- Telegram Widgets docs: https://core.telegram.org/bots/widgets
- Bot API: https://core.telegram.org/bots/api
- Важное состояние на 20 ноября 2026: production-доступность HTML Widgets для обычных ботов требует отдельного подтверждения; сообщения об ограничении: https://github.com/tdlib/telegram-bot-api/issues/947
- **Никакой Telegram Widget в этой ветке не отправляется**. Демо в обычном браузере не доказывает поддержку Telegram.
- Если API недоступен, fallback — Telegram inline-кнопка, серверный spin и готовая короткая анимация или карточка.
- Публичную HTML-страницу нельзя считать авторизованным Telegram-сценарием.

## Приёмка

1. Node.js unit test: сумма весов и точные границы.
2. Проверка обратной геометрии остановки для всех секторов и разных текущих углов.
3. Проверка на реальных клиентах Telegram отдельным согласованным этапом после официального разрешения API.
4. Перед платным MVP обязательно: параллельные запросы, idempotency, crash recovery, баланс, аудит и защита от повторной выдачи.
