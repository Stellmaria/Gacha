## Перед началом

- Цель: устранить регрессию, где живой Telegram показывает две пустые окружности вместо цветного колеса и рубинового центра.
- Источник: пользовательский скриншот от 2026-11-21 и успешный, но ложноположительный, live run `44830274337`.
- База: `main@136f752e274b08ec27483e42f541ad7e003f2ba8`, prior PR #13.
- Объём: корректный Z-order фигур в обоих TGS слоях; автотест по реальному растровому представлению TGS JSON.
- Готовность: проверка шести отдельных цветных секторов, красной центральной геммы и прозрачного фона под Pillow в GitHub CI; не утверждать живое качество без отдельной Telegram приёмки.
- Риск: TGS — упрощённая векторная модель, не исходная роскошная пользовательская картинка. Его нельзя выдавать за визуально утверждённый дизайн. Pixel-perfect Telegram клиент требует live acceptance.

## Действия

- Найдено перекрытие: Lottie обратный порядок рисования в списках `layer.shapes`. Первый вставленный полностью закрашенный диск и базовый хаб рисовались последними.
- Порядок списка перевёрнут, чтобы краска секторов и детали геммы были поверх основания. Добавлен независимый renderer для строгого используемого subset TGS shapes и тестирование его PNG-пикселей.
- Пилот остаётся manual-only. Повторный живой запуск не выполняется без визуальной приемки.
