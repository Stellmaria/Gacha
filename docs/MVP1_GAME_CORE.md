# Gacha MVP-1 — первый проверяемый backend-срез

Основной контракт владелицы (21.11.2026): `Elite`, **10 ежедневных попыток**, общий сброс **00:00 по Europe/Moscow**, старые ежедневные остатки **не суммируются**; бонусные попытки не сгорают, расход **daily → bonus**; одинаковые карточки — **дубли**, сохраняем количество экземпляров. Отдельная игровая валюта — вельветы, не VL/AVL внешних ботов.

## Состав и граница реализации

- `db/migrations/001_mvp1_core.sql` — независимая схема PostgreSQL `gacha`: Telegram players, daily/bonus attempts, grant audits, wallets/ledger, cards, inventory quantity, authoritative spins and delivery outbox. Никакие данные сторонних ботов не читаются.
- `gacha_core/domain.py` — транзакции `GameCore.profile`, `GameCore.spin`, `GameCore.collection`, внутренний идемпотентный `GameCore.grant_bonus` для будущего защищённого админ-интерфейса. Для каждой операции используется **psycopg3 connection с `autocommit=True`**, затем явная `connection.transaction()`.
- Для вращения сервер передаёт **новый `UUID` запроса**. Результат выбирается с `secrets.randbelow`, шансы Classic25/Elite22/Royal19/Epic16/Mythic11/Eternal7. Защита от повторных callback по `(player_id, client_request_id)` и блокировка строки игрока гарантируют одну награду и одну потраченную попытку; после транзакции создаётся outbox-запись. Повтор возвращает прежний spin ID, включая повтор после полуночи.
- По умолчанию **нет ни одной активной карты**. Владелица сообщила, что готово по одной карте каждой из шести редкостей плюс одна вельветовая ивент/адвент-карта, однако файлы с точными именами/проверенными asset IDs пока не найдены в Gacha; **не подставляем вымышленные 12 карт**. Модель `kind=event` сохраняет отдельную карту за пределами шестисекторного колеса. Активировать карту без непустой ссылки на реально утверждённый медиа-ассет запрещает DB CHECK.
- Пока нет постоянно работающего Telegram adapter, настоящего контента/картинок, deploy, вручения награды по outbox и UI. Текущая рулетка `/wheel6` продолжает быть отдельным ручным визуальным тестом. Не отправлять пользователям результат из `GameCore` до подключения защищённого delivery adapter.

## Как проверить на изолированной базе

Создать **новую отдельную** тестовую PostgreSQL 18 базу и задать переменную окружения `GACHA_DATABASE_URL` (только через защищённый runtime, не коммитить строки подключения). Установить `pip install -r requirements-mvp1.txt`, запустить `python -m gacha_core.migrate`; миграция не запускается сама при импорте. Для интеграционных тестов укажите `GACHA_TEST_DATABASE_URL` на **одноразовую БД с именем `gacha_ci` и ролью `gacha_ci`**, поскольку тесты очищают таблицы и создают фикстуры. Защита в тестах отклоняет другие имя базы или роль. Не направлять `GACHA_TEST_DATABASE_URL` в production.

GitHub Actions job `mvp1-postgres-integration` использует **эфемерный PostgreSQL 18 сервис**, повторную миграцию и транзакционные тесты: два пользователя, отсутствие активных карт, повторная выдача, край 23:59:59/00:00 МСК, дубль карты, бонусный остаток, replay, две одновременные крутки и превышение 10. Данные теста не попадают в прод.
