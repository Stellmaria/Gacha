# Gacha (рабочее название)

Независимый прототип коллекционной гачи для Telegram. Финальное название ещё не выбрано.

## Что уже есть

- Два самостоятельных демонстрационных колеса: **ежедневные редкости карточек** (6 секторов, режим по умолчанию) и **призы** (8 секторов).
- Пропорциональные вероятностям SVG-секторы, плавная анимация с указателем, адаптивная тёмная тема.
- Прозрачный выбор исхода и проверки таблиц вероятностей.
- **Реальных списаний и начислений нет.** Telegram проверен через изолированные ручные workflow; разработка PostgreSQL-ядра MVP-1 ведётся отдельно, без деплоя.

## Ежедневная карточная рулетка — 6 редкостей

Это основной экран будущего бота. Игроку будут начисляться бесплатные крутки в настраиваемые утреннее и вечернее окна. **Количество, время, часовой пояс и перенос остатков пока не утверждены**; для тестов используется условный пример 6+6.

| Редкость | Шанс |
| --- | ---: |
| Classic | 25% |
| Elite | 22% |
| Royal | 19% |
| Epic | 16% |
| Mythic | 11% |
| Eternal | 7% |

## Призовая рулетка — 8 секторов

| Приз | Шанс |
| --- | ---: |
| 10 вельветов | 20% |
| 20 вельветов | 20% |
| Classic | 15% |
| 50 вельветов | 15% |
| Elite | 10% |
| 1 крутка | 10% |
| 2 крутки | 5% |
| Royal | 5% |

**Внимание:** это два отдельных набора вероятностей. Связь между ними ещё не утверждена. Ни один исход не меняет баланс игрока.

## Запуск для разработки

Проект не требует зависимостей, npm, Docker или токенов.

```bash
python -m http.server 8000
# открыть http://localhost:8000
```

Либо использовать статический HTTP-сервер. Запускать на production-хостах Velvet не требуется.

## Где хранить токены Telegram

Не вставляйте токен в чат, исходники или переменные `workflow_dispatch`. Для проверки бота используем два GitHub Actions Secrets: `GACHA_BOT_TOKEN` (обычный Telegram) и `GACHA_TEST_BOT_TOKEN` (отдельный Telegram Test Server). [Пошаговая инструкция](docs/BOT_TOKENS.md).

## Тестирование Telegram

Новый fallback для **обычного** Telegram-бота: inline-кнопка, оригинальная прозрачная GIF-анимация остановки на одной из шести редкостей и **отдельное раскрытие результата после задержки**, только ручной GitHub Actions smoke без начислений. [Порядок запуска](docs/TELEGRAM_INLINE_FALLBACK.md). Для текущего тестового бота используется **уже сохранённый** `GACHA_TEST_BOT_TOKEN` через обычный Telegram Bot API. Отдельный `GACHA_BOT_TOKEN` пока не требуется. [Окружения и проверка](docs/BOT_TOKENS.md).


GitHub CI проверяет только код и логику, **не работу Telegram-клиента**. Для Widgets нужно отдельное тестовое окружение Telegram и тестовый бот; для публичного бота готовим fallback с inline-кнопкой и анимацией. [План тестирования](docs/TELEGRAM_TEST_PLAN.md).

## Проверки

```bash
node --test
node --check src/app.mjs
node --check src/wheels.mjs
```

Эти же команды выполняет GitHub Actions на `ubuntu-latest`. Проект не содержит секретов и не требует собственных машин.

## Telegram

Планировалась интеграция через Telegram HTML Widgets, но её реальная production-доступность должна быть проверена отдельно до включения. Утверждённая анимация уже проходит **ручной Telegram smoke** через `/wheel6`, но постоянный бот и реальные награды ещё не подключены. Подробнее: [технический контракт](docs/TECHNICAL.md).

Проект не зависит от `Stellmaria/Velvet`, Dominus, Demian или других репозиториев.

## Новый тест внутри чата: Royal TGS/Lottie (без GIF и MP4)

Для тестирования короткой телеграмной последовательности создан **отдельный ручной** workflow
[Royal chat-native TGS pilot](https://github.com/Stellmaria/Gacha/actions/workflows/telegram-chat-royal-pilot.yml).
Он отправляет статичное колесо, после нажатия один короткий TGS-запуск, затем TGS-вращение
с неподвижными стрелкой и рубином, отдельный результат и **демонстрационную** карточку.
Тест намеренно фиксирован на **ROYAL** и не начисляет наград; существующая рабочая
проверка всех шести редкостей остаётся без изменений. Визуальный TGS-диск упрощён:
это прототип механики, не готовая копия детализированного оригинала.

Для запуска в существующем тестовом боте отправь в личный чат `/wheel`, затем вручную
запусти workflow на `main` и нажми полученную кнопку в течение 80 секунд.
Подробнее: [docs/GACHA_CHAT_ROYAL_TGS_PILOT.md](docs/GACHA_CHAT_ROYAL_TGS_PILOT.md).

## Velvet Wheel в Telegram: все шесть утверждённых исходов (тест)

Для проверки полного игрового сценария без Mini App предусмотрен **отдельный ручной**
[Telegram Wheel6 smoke](https://github.com/Stellmaria/Gacha/actions/workflows/telegram-wheel6-smoke.yml).
Он выбирает редкость на стороне сервера по весам 25/22/19/16/11/7, использует
один из **шести оригинальных MP4** `wheel/videos/` и старается заменить
стартовое фото анимацией прямо в том же сообщении. После завершения ролика
обновляет подпись с редкостью. Если Telegram явно не поддерживает замену
медиа — отправляет одну отдельную анимацию. Карты, попытки и валюту не затрагивает.

Запуск только после свежей личной команды `/wheel6` существующему тестовому
боту и ручного запуска workflow: [инструкция](docs/TELEGRAM_WHEEL6_INLINE_PREVIEW.md).
Это **визуальный тест**, а не постоянно работающий игровой бот.

## MVP-1 · PostgreSQL game core (в разработке)

Игра переходит от визуальных smoke-тестов к независимому серверному ядру:
**10 ежедневных круток при 00:00 МСК**, отдельные бонусные, дубли карт,
история и надёжная транзакционная выдача исхода через PostgreSQL.
Реальные семь карт (шесть редкостей плюс вельветовая ивент-карта) будут
подключены только после проверки исходных файлов; никаких замен из стоков.
Документация и пределы реализации: [MVP1_GAME_CORE.md](docs/MVP1_GAME_CORE.md).
Пока **нет постоянно работающего Telegram-бота, базы на сервере или реальных
начислений** — это первая отдельная backend-реализация без деплоя.
