# Тестирование Telegram без серверов Velvet

Дата: 20.11.2026. В этой ветке реальные вызовы Telegram не выполнялись.

## Что нам требуется проверить

Главное колесо гачи — **ежедневные карточки**, шесть секторов с весами 25/22/19/16/11/7. Призовая рулетка с 8 исходами — второстепенный отдельный режим. Настройки ежедневной выдачи утром/вечером пока черновые, в unit-тестах 6+6 — только фикстура.

## Два маршрута

### A. Widget: только официальный Telegram test server до восстановления production

- Официальные [Widgets](https://core.telegram.org/bots/widgets).
- Публичный Bot API может возвращать `INPUT_MEDIA_WIDGET_NOT_ALLOWED` для обычных ботов (разработчик подтвердил ограничение 13.11.2026): [tdlib/telegram-bot-api#947](https://github.com/tdlib/telegram-bot-api/issues/947). Таблица доступности в документации по состоянию на 20.11 всё ещё оптимистична.
- На **отдельном test server** документация разрешает все widget-сценарии. Это не значит, что продакшен-бот поддерживает Widgets.
- Нужен отдельный **тестовый Telegram-аккаунт и тестовый бот** через BotFather внутри тестового окружения. Обычный токен production BotFather не заменяет тестовый.
- Официальная инструкция: https://core.telegram.org/bots/features#testing-your-bot . Для Telegram Desktop: открой Settings, затем с Shift+Alt щёлкни правой кнопкой по Add Account, выбери Test Server (в интерфейсах горячие клавиши могут отличаться).
- Тестовые Bot API методы: `https://api.telegram.org/bot<TOKEN>/test/METHOD_NAME`. Не размещать настоящий TOKEN в issue, PR, log или URL рабочего чата.

Проверить в ручной приёмке: `getMe` тестового бота; `sendWidget` минимального HTML; обработку `widget_query` и ответ `answerWidgetQuery`; повтор нажатия; сворачивание/повторное открытие; Android и Desktop.

### B. Обычный Bot API: реальный public bot с fallback

- `sendMessage` с inline-кнопкой «Крутить»; пользователь получает `callback_query`.
- Подтвердить callback через `answerCallbackQuery` для устранения индикатора ожидания.
- Надёжный server-side idempotent spin и квота (нельзя выбирать награду в HTML/JS клиента).
- Отправить заранее подготовленное GIF/MP4 (`sendAnimation`) с остановкой на заранее выбранной **сервером** редкости либо `sendVideo`; затем отдельную карточку через `sendPhoto`.
- Картинка с собственным шестисекторным колесом допускается; стандартный Telegram `🎰` имеет лишь 64 исхода и фиксированный дизайн, потому не заменяет наше колесо с точными шестью весами.
- Сервер — вне production Velvet. Для постоянной доступности требуется независимый процесс или serverless webhook с внешней БД; GitHub Actions не заменяет бесконечный polling/webhook.
- На первом этапе ничего не выдавать и не списывать, только выводить «демо».

## Что проверяет GitHub CI

- `node --test`: веса обоих колёс, геометрия указателя, настраиваемые ежедневные гранты, стабильные ключи грантов, переход времени/DST.
- `node --check` модулей JavaScript.
- Статические проверки наличия браузерной страницы.
- Ни один pull_request workflow не должен иметь доступ к секретам BotFather и не должен отправлять реальные сообщения.

## Будущая серверная гарантия

Уникальный ключ выдачи: `(user_id, campaign_id, local_date, window_id)`; календарь в **фиксированном часовом поясе игры**, не в часовом поясе телефона. Два окна одного дня независимы. Отдельный unique `spin_request_id` связывает расход крутки, результат и экземпляр карточки в одной транзакции. Повтор webhook/callback не приводит к повторной награде.

Возможность суммирования неиспользованных попыток, дневной reset и финальные количества будут согласованы отдельно. Unit-тесты не доказывают транзакционную защиту — для неё понадобятся интеграционные тесты с БД.

## Матрица приёмки

| Что | GitHub CI | Telegram live |
| --- | --- | --- |
| Весовая выборка | Да | Не требуется |
| Утренние/вечерние окна | Да, функции | Нужна БД для фактических грантов |
| Мобильный вид и анимация | Ограниченно (базовая статика) | Да |
| HTML Widget test server | Нет, без токена | Только отдельный тестовый бот |
| Обычная inline-кнопка | Нет, mock далее | Да |
| Реальная карточка и инвентарь | Нет | Нужен сервис и БД |

## Подключение токена для ручной проверки

Инструкция: [BOT_TOKENS.md](BOT_TOKENS.md). Manual-only workflow `telegram-preflight.yml` вызывает только `getMe` и выбирает соответствующее окружение. Secrets остаются вне репозитория и не используются в pull request проверках. Этот workflow не является приёмкой Widgets и не запускает постоянного бота.
