# Telegram обычный бот — ручная демо-рулетка

## Зачем

Обнаружено, что `GACHA_TEST_BOT_TOKEN` принадлежит обычному Telegram (GitHub [workflow 44793387784](https://github.com/Stellmaria/Gacha/actions/runs/44793387784)). Для настоящего HTML Widget всё ещё нужен отдельный тестовый бот на **Telegram Test Server**.

Параллельно можно проверить крутку с обычным ботом **без Widgets**: inline-кнопка в сообщении и GIF-анимация остановки шести редкостей. Код и ресурсы полностью отдельны от Velvet.

## Подготовка

- Сохранить токен **обычного** BotFather в GitHub Actions Secret `GACHA_BOT_TOKEN`: https://github.com/Stellmaria/Gacha/settings/secrets/actions
- Не перемещать и не использовать токен обычного бота в `GACHA_TEST_BOT_TOKEN`. Его нужно будет заменить на новый, созданный в Test Server.
- Если у бота уже есть webhook или getUpdates poller, новый ручной smoke не сможет корректно получать события, и должен завершиться без вмешательства в этот runtime.

## Запуск (после merge workflow в main)

1. В обычном Telegram открой личный чат созданного гача-бота и отправь `/wheel` (именно так, без дополнительных символов).
2. Открой GitHub Actions → `Telegram wheel fallback — MANUAL DEMO` → Run workflow, ветка `main`: https://github.com/Stellmaria/Gacha/actions/workflows/telegram-inline-smoke.yml
3. Workflow допускает только **один** свежий приватный диалог за последние 10 минут. Если несколько человек прислали `/wheel`, он безопасно завершится без отправки.
4. Бот отправляет сообщение с кнопкой «Крутить (демо)». Нажать в течение **80 секунд**.
5. GitHub-hosted runner выбирает редкость по точным шансам 25/22/19/16/11/7, генерирует GIF и отправляет в личный чат. Игра ещё **не** начисляет карточки, не списывает попытки и не меняет вельветы.

## Безопасность и ограничения

- Workflow запускается только вручную, без `push`/`pull_request` и без периодических расписаний.
- Никаких секретов, имён, Telegram chat ID, ответов Bot API или полных HTTP URL в логах.
- Для проверки используется исключительно `GACHA_BOT_TOKEN`, никогда `GACHA_TEST_BOT_TOKEN`.
- Метод строго ограничен `getUpdates`, `sendMessage`, `answerCallbackQuery`, `editMessageReplyMarkup`, `sendAnimation`. Платежи и аккаунтные операции недоступны.
- Для пользовательской активности потребуются отдельные backend + БД: 80-секундный GitHub Action не может работать постоянно.
- Получившаяся GIF — только демонстрация. Telegram может её зациклить. Результат фиксируется в подписи и совпадает с сектором, на котором остановилась стрелка в конце.
- Только одно успешное нажатие за один ручной запуск, повтор не выдаёт ничего.
- Реальную Telegram-приёмку нельзя объявлять пройденной только по юнит-тестам и зелёному CI.

## Дальше

Отдельный Telegram TEST токен → проверить HTML Widget по инструкции `docs/BOT_TOKENS.md`. После тестов сравнить, какой UX подходит продукту, и выбрать отдельный runtime (не сервер Velvet).
